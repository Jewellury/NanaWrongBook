## 审计结论（大白话）

**总体判定：⚠️ 有条件通过（代码无逻辑 bug，但移动端布局有疏漏，导致按钮可能在视口外不可见）**

代码层面，按钮是存在的（`capture/page.tsx` 第 366-374 行），条件渲染也是对的（保存成功后显示）。没有 CSS 把它藏起来，也没有条件判断把它排除在移动端之外。

但问题很可能出在**页面布局**上——手机上屏幕本来就小，拍题区域占了 52% 的视口高度，保存成功后底部按钮区的内容从 60px 膨胀到约 200px（多了"已收好"消息框 + "去知识地图看看" + "给这道题挂个知识点" + "再拍一道"），结果就是这几个按钮被挤到屏幕底下去了。页面按理说能滚动，但用户可能不知道需要往下滑。

特别是 iPhone 的 Safari，`100vh` 会比实际可视区域高（因为包含了浏览器地址栏），这会让 `mt-auto`（自动底对齐）把按钮推到更下面，用户更不易发现。

这不是 JS 代码的 bug，是**移动端布局设计上的疏漏**——保存成功后应该把视图自动滚动到新按钮的位置，或者调整布局避免底部按钮溢出。

## 问题定位（详细分析）

### 问题 1：[P2] 保存成功后按钮可能在移动端视口外不可见

**位置**: `src/app/nana/capture/page.tsx`

**代码片段（按钮区域，第 355-382 行）**：
```tsx
{saved ? (
  <>
    <Link href="/nana/knowledge-map"
      className="...">
      去知识地图看看
    </Link>
    <Link href="/nana/knowledge-map?openCases=1"
      className="...">
      <span className="inline-flex items-center gap-1.5">
        <Tag className="size-4" />
        给这道题挂个知识点
      </span>
    </Link>
    <button onClick={handleTakeAnother} ...>再拍一道</button>
  </>
) : (...)}
```

**问题根因分析**：

页面的布局结构是：
```
<div class="mx-auto flex min-h-screen max-w-md flex-col">
  ← 顶栏 42px
  ← 题图区域 52vh（≈350-440px, min-h-[280px]）
  ← 三 tab 栏 ~45px
  ← flex-1 剩余空间（VoiceRecorder + mt-auto 底部操作区）
```

移动端计算（以 iPhone 12 Pro 844vh 为例）：
| 区域 | 高度 |
|------|:----:|
| 顶栏 | 42px |
| 题图（52% of 844） | 439px |
| Tab 栏 | ~45px |
| flex-1 可用空间 | 844 - 526 = **318px** |
| VoiceRecorder 完成态 | ~100px |
| 底部按钮区（idle 态：1 按钮） | ~60px |
| 底部按钮区（saved 态：消息框 + 计数 + 3 按钮） | **~200px** |

- **保存前**：100 + 60 = 160px < 318px ✅ 有富余
- **保存后**：100 + 200 = 300px < 318px ✅ 仍够（iPhone 12 Pro 等大屏手机）
- **iPhone SE（667vh）**：flex-1 = 667 - 434 = 233px，保存后 100 + 200 = 300px > 233px ❌ 溢出

溢出后：
- `mt-auto` 失效（没有富余空间可以顶到底部）
- 底部按钮在 VoiceRecorder 下方按文档流排列
- 整体内容高度约 700+px，超出 667px 视口
- 页面理论上能滚动，但有三个叠加因素让用户不易发现按钮：

  **因素 A：iOS Safari `100vh` bug**
  - iOS Safari 的 `100vh` 比实际可视区域高（约 +70px，包含了地址栏+工具栏）
  - `min-h-screen` 设了一个比屏幕大的基准高度
  - `mt-auto` 把按钮推到这个"虚高"容器的底部
  - 实际可视区域的底部可能只到容器的一半

  **因素 B：无自动滚动**
  - 保存成功后，按钮区从 60px 膨胀到 200px
  - React 不自动滚动到新内容位置
  - 用户点完"收好这道题"后手指移开，页面之前已经自动滚到底部
  - 新内容出现在下方但用户没意识到需要再滑一下

  **因素 C：52vh 题图区占据过多空间**
  - 题图区域固定 52vh，在小屏手机上吃掉超过一半空间
  - 留给底部操作区的空间很紧张

### 问题 2：[P2] createCase API 在移动端网络下可能超时导致按钮不出现

**位置**: `src/app/nana/capture/page.tsx` 第 162-194 行

**代码**：
```tsx
try {
  const artifacts = await buildArtifacts();
  await createCase(artifacts);   // ← 1MB+ POST，移动端可能超时
  setSaveState("saved");         // ← 只有成功才显示按钮
} catch {
  setSaveState("error");         // ← 失败显示"没存成功，再试一次"
  setSaveMsg(FAILURE_MSG);
}
```

移动端网络在 4G/5G 下传输 1MB+ base64 可能需要数秒，存在超时可能。如果 `createCase` 超时或失败，`saveState` 会变成 "error"，显示错误信息而不是保存成功的按钮。用户反馈中没有提到看到了错误信息，但超时行为取决于实际网络环境。

这个问题不完全是代码 bug，但缺少超时提示（用户不知上传正在进行中，只能看到"正在收…"等很久）。

## 用户验证指南

如果要在手机上验证按钮是否存在，请按以下步骤：

1. 确保代码已包含 commit `1b7d856`（`git log --oneline | grep 1b7d856`）
2. 本地开发模式运行 `npm run dev`
3. 手机和电脑在同一局域网，访问电脑 IP 的 3001 端口（如 `http://192.168.x.x:3001`）
4. 登录后 → 拍题（或从相册选一张）→ 点"收好这道题"
5. **保存成功后**：注意观察页面底部是否出现三个按钮——"去知识地图看看"（绿色）、"给这道题挂个知识点"（琥珀色边框）、"再拍一道"（文字链接）
6. 如果只看到"已收好"消息但看不到按钮 → **向下滑动页面** → 按钮应该就在下面
7. 点击"给这道题挂个知识点" → 应跳转到知识地图页且自动弹出"最近拍过的题"浮层
