# 孩子视角的最小闭环与分层自动化测试

> 日期：2026-07-12
> 状态：方向已形成；“先冻结最小闭环验收契约再执行测试代码”仍待用户最终确认

## 背景

用户在生产手机浏览器中反复发现点击反馈慢、页面毛刺和完整流程不顺，希望借助自动化与 AI 减少每次部署后的人工点测。项目已经拥有 Playwright 移动端主链路、脱敏手拍题图、录音与真实豆包能力，但既有自动化主要验证页面可达和单题保存，尚不能证明孩子最终得到了一份按课本章节整理、可查看、可打印的错题集。

## 长期目标

测试的最终对象不是现有页面结构，而是孩子的产品结果：

```text
拍题 → 可选讲思路 → 先保存 → AI 整理
    → 自动课本分类 → 必要时人工纠错
    → 多题按章节汇总 → 知识地图显示收过题证据
    → 打印成可复习的错题集
```

## 采用的测试结构

1. 确定性 CI：临时数据库 + 本地兼容假 Provider，验证真实 `/process`、转码、事务和落库。
2. 性能与毛刺证据：采集步骤截图、网络、控制台、页面指标；先建立趋势，不在不稳定公共 runner 上贸然设绝对性能硬门禁。
3. 真实 Provider Smoke：专用测试账号验证真实识图、转写、分类和反馈；具备精确清理能力前不周期写生产。
4. AI 体验评审：不同于产品模型的评审模型阅读脱敏证据包，必须引用截图、步骤和指标；只提供建议。
5. 真机抽检：保留相机、麦克风授权、iOS、微信和实际打印检查。

## 产品契约

### 核心闭环

- 题图保存不等待 AI；孩子可以继续拍下一题。
- 录音可选，无录音也能完成错题整理。
- AI 输出只承诺摘要、转写、课本分类、轻反馈、可能方向和下一步建议，不承诺完整 OCR、答案或掌握诊断。
- 多道题按孩子熟悉的课本章节形成汇总，并能生成简洁打印材料。

### 纠错恢复

- AI 分类错误时，孩子可以修改 `TextbookTopic`；手动结果优先且不被后续 AI 覆盖。
- 低置信图片进入“未分类/暂未覆盖”，不得伪造分类。
- 音频失败不阻塞题图整理；AI/网络失败后题仍已保存并可重试。
- 手动分类是恢复路径，不是每道题的必经步骤。

### 辅助解释

- `KnowledgeNode` 只承担内部系统分类与知识地图证据。
- 题目映射后地图可显示琥珀色“收过题”，但不得写 `StudentNodeState` 或变成绿色掌握。
- 原题图和系统细节按需展开，不应挤占题目汇总的主要阅读空间。

## 关键技术边界

- 不用 `page.route()` 拦截 `/api/nana/cases/:id/process`，因为这会绕过真实持久化闭环。假 Provider 必须放在最外部模型调用边界。
- 浏览器录音自动化优先使用 Chromium fake media + 脱敏数学口述音频，保留真实 `MediaRecorder` 和服务端 ffmpeg 路径。
- 测试分类必须跨多个实际课本章节；只有函数题不能证明汇总分组有效。
- 除单题黄金路径外，需要三题连续采集和约 30 题汇总规模场景，避免只在空数据下看起来顺畅。
- 生产写入型 Smoke 必须记录本次 Case ID 并精确清理；清理接口属于破坏性能力，必须单独计划、审计和确认。

## 未采用的方案

- 让 AI 自由点击页面并把主观印象直接当发布门禁：不可复现，也无法替代硬断言。
- 每次 E2E 全局保留所有视频和 trace：成本高、拖慢 CI；应按失败或评审任务分层保留。
- 用系统 48 个 KnowledgeNode 直接作为孩子手动分类列表：不符合孩子的课本认知层。
- 在公共 CI runner 上立刻用固定毫秒阈值阻塞发布：易产生噪声和错误回归判断。

## 待确认与重访条件

### 待用户确认

- 在开始测试框架代码前，先建立一份权威的 `Nana v1 最小错题集闭环验收契约`，列出功能 ID、用户结果、数据落点、失败降级、当前实现状态和测试层映射。

### 重访条件

- 当真实 Provider Smoke 连续稳定且生产清理能力审计通过，可将部分真实语义检查升级为发布门禁。
- 当性能采集积累足够稳定样本，可把滚动基线回归升级为告警，极少数稳定指标再考虑硬门禁。
- 当完整 OCR、重复题识别或深度诊断进入产品范围时，应新增独立契约，不应悄悄扩张当前最小闭环。

## 分类

- 事实：现有自动化未覆盖完整错题集结果，真机仍发现毛刺与慢。
- 偏好：尽量用自动化和 AI 减少重复手机点测，但保留必要真机检查。
- 原则：测试围绕孩子得到的产品结果；硬断言与 AI 体验评审分离。
- 待确认：是否先冻结最小闭环验收契约再启动 R1a 实现。
