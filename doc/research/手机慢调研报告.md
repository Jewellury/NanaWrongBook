## 1. 首屏加载：73 个 "use client" 的 code splitting

**关键认知纠偏**：`"use client"` 不等于"不 SSR"。客户端组件在 App Router 里默认仍会 SSR，`"use client"` 只是标记"这些组件的 JS 要打进客户端 bundle"。所以 73 个客户端组件本身不是问题，问题是**它们全被打进了客户端 bundle**。

App Router 已经自动按**路由段**做 code splitting——每个 `page.tsx` 是独立 chunk。所以如果 73 个组件分散在多个路由里，它们其实已经被拆开了。2.67MB 说明你有**巨大的共享 chunk**或**重依赖被 eager import**。

第一步永远是定位，别凭感觉：

```js
// next.config.ts
import withBundleAnalyzer from '@next/bundle-analyzer'
const analyze = withBundleAnalyzer({ enabled: process.env.ANALYZE === '1' })
export default analyze({
  experimental: {
    // 图标库/工具库的 tree-shaking，避免 barrel import 把整包拉进来
    optimizePackageImports: ['lucide-react', 'date-fns', 'lodash-es'],
  },
})
```

`ANALYZE=1 next build` 看火焰图。高中生 App 里常见的"隐形 2MB"来源：图标库 barrel import、`moment`（换 `date-fns`/`dayjs`）、整个 UI 组件库、以及把相机/录音/canvas 这类只在某一步用到的重逻辑打进了首屏。

**次重的、只在特定步骤才用的组件用 `next/dynamic` 懒加载**（相机、录音、波形、图片压缩 worker 的调用方都属于这类）：

```tsx
'use client'
import dynamic from 'next/dynamic'

// ssr:false 用于依赖 window/navigator.mediaDevices 的组件
// 注意：next/dynamic 的 ssr:false 在 Server Component 中会构建报错，
// 必须在 Client Component 里调用——你全是 "use client"，所以没问题
const CameraCapture = dynamic(() => import('./CameraCapture'), {
  ssr: false,
  loading: () => <CameraSkeleton />,
})
const AudioRecorder = dynamic(() => import('./AudioRecorder'), {
  ssr: false,
  loading: () => <RecorderSkeleton />,
})
```

**`loading.tsx` + Suspense 的正确配合**：`loading.tsx` 是路由段级的自动 Suspense boundary，路由切换时立刻显示，无需你手写 `<Suspense>`：

```
app/
  (auth)/login/page.tsx
  capture/
    loading.tsx      ← 进入 /capture 立即渲染骨架屏
    page.tsx
  record/
    loading.tsx
    page.tsx
```

组件级细粒度加载再用 `<Suspense>` 包 `dynamic` 组件。**规则**：`loading.tsx` 管"路由跳转时的等待"，`<Suspense>` 管"页面内某块异步内容的等待"，两者互补不冲突。

**最该做的结构性改动**：审视这 73 个组件——纯展示页（题目列表、历史记录、结果页）根本不需要 `"use client"`，去掉后它们的 JS 完全不进客户端 bundle，只留相机/录音/上传这几个真正交互的岛屿是客户端。这是把 900KB gzip 往下打的最大杠杆。

**中国浏览器差异**：4G 下 gzip 900KB 首包要好几秒。确保腾讯云开了 Brotli（比 gzip 再小 ~15%），并给关键路由加 `<link rel="prefetch">`。微信/UC 的 X5 内核对 HTTP/2 支持没问题，但对 `<script type="module">` 的老版本可能降级，Next.js 默认 target 已经够安全。

## 2. 拍照体验：input capture + OffscreenCanvas 压缩

**`<input capture="environment">` 已知坑**：

* **iOS Safari**：加了 `capture` 会**直接调起相机、去掉"从相册选"选项**。很多产品其实想两者都给，此时应**去掉 `capture`**，只留 `accept="image/*"`，让用户选拍照或相册。
* **Android Chrome**：`capture="environment"` 调后置摄像头，符合预期。
* **HEIC**：iOS 通过 `<input>` 拍照通常回传 JPEG，但从相册选可能给 HEIC，canvas 解不了。要 `try/catch` 兜底。
* **EXIF 旋转**：相机照片带旋转标记，`drawImage` 到 canvas 会丢失方向导致图片躺倒。这是最常见的 bug，下面用 `createImageBitmap({imageOrientation:'from-image'})` 解决。
* **微信内置浏览器（最大的坑）**：微信 Android（X5 内核）经常**忽略 `capture`**、弹自己的"拍照/相册"选择器；`accept` 有时也不生效。微信里最可靠的是用**微信 JS-SDK 的 `wx.chooseImage`**。如果你的用户主要在微信里点开链接，必须做微信环境检测并走 JS-SDK 或引导"在浏览器打开"。

```tsx
const isWechat = /micromessenger/i.test(navigator.userAgent)
// isWechat ? 引导用系统浏览器打开 / 走 wx.chooseImage : 用原生 <input>
```

**在 Web Worker 里用 OffscreenCanvas 压缩，主线程零卡顿**。关键技巧：**把 File 直接 transfer 给 worker**，连 `createImageBitmap` 都在 worker 里做，主线程完全不碰解码：

```js
// image-worker.js
self.onmessage = async (e) => {
  const { file, maxEdge = 1600, quality = 0.8, id } = e.data
  try {
    // createImageBitmap 在 worker 中可用；from-image 修正 EXIF 方向
    const bmp = await createImageBitmap(file, { imageOrientation: 'from-image' })
    const scale = Math.min(1, maxEdge / Math.max(bmp.width, bmp.height))
    const w = Math.round(bmp.width * scale)
    const h = Math.round(bmp.height * scale)
    const canvas = new OffscreenCanvas(w, h)
    const ctx = canvas.getContext('2d')
    ctx.drawImage(bmp, 0, 0, w, h)
    bmp.close()
    const blob = await canvas.convertToBlob({ type: 'image/jpeg', quality })
    self.postMessage({ id, blob }) // Blob 可结构化克隆，无需 transfer
  } catch (err) {
    self.postMessage({ id, error: String(err) })
  }
}
```

```ts
// 调用方（含降级）
async function compressImage(file: File): Promise<Blob> {
  if (typeof OffscreenCanvas !== 'undefined' &&
      typeof createImageBitmap !== 'undefined') {
    return new Promise((resolve, reject) => {
      const worker = new Worker(new URL('./image-worker.js', import.meta.url))
      const id = crypto.randomUUID()
      worker.onmessage = (e) => {
        worker.terminate()
        e.data.error ? reject(new Error(e.data.error)) : resolve(e.data.blob)
      }
      worker.postMessage({ file, id })
    })
  }
  return compressOnMainThread(file) // 降级
}

// 降级：主线程 <canvas>，兼容不支持 OffscreenCanvas 的旧内核
async function compressOnMainThread(file: File): Promise<Blob> {
  const url = URL.createObjectURL(file)
  try {
    const img = await new Promise<HTMLImageElement>((res, rej) => {
      const i = new Image()
      i.onload = () => res(i); i.onerror = rej; i.src = url
    })
    const maxEdge = 1600
    const scale = Math.min(1, maxEdge / Math.max(img.width, img.height))
    const canvas = document.createElement('canvas')
    canvas.width = Math.round(img.width * scale)
    canvas.height = Math.round(img.height * scale)
    canvas.getContext('2d')!.drawImage(img, 0, 0, canvas.width, canvas.height)
    return await new Promise<Blob>((res) =>
      canvas.toBlob((b) => res(b!), 'image/jpeg', 0.8))
  } finally {
    URL.revokeObjectURL(url)
  }
}
```

**兼容性**：`OffscreenCanvas.convertToBlob` 需 Chrome 69+ / Firefox 105+ / **Safari 16.4+**；`createImageBitmap` 基础功能 Chrome 50+ / Safari 15+，但 `imageOrientation` 选项 Safari 支持较晚（Safari 17 才稳）。所以对 iOS 16.4 以下和老 UC/QQ 内核，务必走上面的主线程降级，且**EXIF 方向在降级路径可能丢**——需要时用轻量库（如 `exifr`）读方向手动旋转，或干脆信任现代浏览器 CSS `image-orientation: from-image` 的默认行为（仅对 `<img>` 有效，canvas 无效，这正是坑所在）。

**中国浏览器差异**：UC/QQ 的老 X5 内核常缺 `OffscreenCanvas`，降级路径是必需的，不是可选的。

## 3. 录音体验：MediaRecorder iOS 坑与波形

**iOS Safari 16+ 已知问题**：

* **MIME 类型**：iOS 只支持 `audio/mp4`（AAC），**不支持 `audio/webm`**；Chrome/Firefox 支持 `webm/opus` 但（历史上）不支持 `mp4`。必须特性检测后择一，否则拿到空 blob：

```ts
function pickMimeType(): string {
  const prefs = ['audio/mp4', 'audio/webm;codecs=opus', 'audio/webm']
  return prefs.find((t) => MediaRecorder.isTypeSupported?.(t)) ?? ''
}
const mimeType = pickMimeType()
const recorder = new MediaRecorder(stream, mimeType ? { mimeType } : undefined)
```

* **后台/锁屏即停**：iOS 上页面切后台或锁屏，录音会中断。要监听 `visibilitychange` 提示用户。
* **必须用户手势 + HTTPS**：`getUserMedia` 必须在点击等手势回调里调用。
* **路由切换反复弹权限**（搜索确认到 2025 年中仍存在）：iOS SPA 里跨路由 `getUserMedia` 会重复弹权限。对策——**在一个稳定的、不随路由卸载的组件里持有 MediaStream**，别让录音组件每次路由都重挂载。

**权限预检（Permissions API）**：`navigator.permissions.query({name:'microphone'})` 在 **iOS Safari 上不支持**（Firefox 也部分不支持）。所以别依赖它做预检，正确做法是 try/catch 包 `getUserMedia` 并按错误名分支：

```ts
async function requestMic(): Promise<MediaStream | null> {
  // Permissions API 仅作可用时的软提示，不可依赖
  try {
    if (navigator.permissions?.query) {
      const s = await navigator.permissions.query({ name: 'microphone' as PermissionName })
      if (s.state === 'denied') { showEnableMicGuide(); return null }
    }
  } catch { /* Safari 抛错，忽略，直接走下面 */ }

  try {
    return await navigator.mediaDevices.getUserMedia({ audio: true })
  } catch (err: any) {
    if (err.name === 'NotAllowedError') showEnableMicGuide()      // 用户拒绝
    else if (err.name === 'NotFoundError') showNoMicMessage()     // 无设备
    return null
  }
}
```

**波形：用真实 AnalyserNode，别用装饰性动画**。原因是给用户"确实在录"的信心，成本也很低。iOS 关键坑：autoplay policy 会 suspend AudioContext，**必须在手势里 `resume()`**：

```ts
function setupWaveform(stream: MediaStream, canvas: HTMLCanvasElement) {
  const AC = window.AudioContext || (window as any).webkitAudioContext // iOS 前缀
  const audioCtx = new AC()
  if (audioCtx.state === 'suspended') audioCtx.resume() // iOS 必需
  const src = audioCtx.createMediaStreamSource(stream)
  const analyser = audioCtx.createAnalyser()
  analyser.fftSize = 256
  src.connect(analyser)
  const buf = new Uint8Array(analyser.frequencyBinCount)
  const ctx = canvas.getContext('2d')!
  let raf = 0
  const draw = () => {
    raf = requestAnimationFrame(draw)
    analyser.getByteTimeDomainData(buf) // 时域波形；频谱用 getByteFrequencyData
    ctx.clearRect(0, 0, canvas.width, canvas.height)
    ctx.beginPath()
    const slice = canvas.width / buf.length
    for (let i = 0; i < buf.length; i++) {
      const y = (buf[i] / 128) * (canvas.height / 2)
      i ? ctx.lineTo(i * slice, y) : ctx.moveTo(0, y)
    }
    ctx.stroke()
  }
  draw()
  return () => { cancelAnimationFrame(raf); audioCtx.close() }
}
```

**中国浏览器差异**：微信内置浏览器的音频/录音受限严重，AudioContext 常需 `WeixinJSBridgeReady` 事件里 resume；纯 `getUserMedia` 录音在微信里体验差，如果录音是核心流程，强烈建议引导"在系统浏览器打开"。

## 4. 上传体验：进度条、base64 vs FormData、离线队列

**fetch 不支持上传进度**（Chrome 有 duplex streaming request body，但 Safari 不支持，不可靠），用 XHR：

```ts
function uploadWithProgress(
  url: string, body: FormData | Blob,
  onProgress: (pct: number) => void,
): Promise<Response> {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest()
    xhr.open('POST', url)
    xhr.upload.onprogress = (e) => {
      if (e.lengthComputable) onProgress(Math.round((e.loaded / e.total) * 100))
    }
    xhr.onload = () => (xhr.status < 400
      ? resolve(new Response(xhr.response, { status: xhr.status }))
      : reject(new Error(`HTTP ${xhr.status}`)))
    xhr.onerror = () => reject(new Error('network'))
    xhr.ontimeout = () => reject(new Error('timeout'))
    xhr.timeout = 30000 // 4G 下给足超时
    // 别手动设 Content-Type，FormData 会自带 boundary
    xhr.send(body)
  })
}
```

**base64 vs FormData——移动端一定选 FormData（multipart 二进制）**：

|       | base64（你现在的方案）    | FormData / multipart |
| ----- | ----------------- | -------------------- |
| 传输体积  | +33% 膨胀           | 原始二进制                |
| 编码开销  | 主线程阻塞数百 ms（1MB 图） | 零，浏览器直传              |
| DB 存储 | 文本，+33% 磁盘        | BLOB 或对象存储只存 key     |
| 进度条   | 可以                | 可以                   |

结论：**把 base64 全链路换成二进制**。前端 `FormData.append('image', blob, 'q.jpg')`，后端存腾讯云 COS，SQLite 只存 COS 的 object key。香港服务器 + 国内 4G 的 100-200ms 延迟下，这个改动省的字节和 CPU 是实打实的。

**离线队列 / 断点续传**：Background Sync API（`registration.sync.register()`）**只有 Chrome/Android 支持，iOS Safari 和 Firefox 完全不支持**。所以不能只靠它。跨平台方案是 **IndexedDB 队列 + `online` 事件/前台唤醒时重试**，Chrome 上再叠加 Background Sync：

```ts
import { openDB } from 'idb'
const db = openDB('upload-queue', 1, {
  upgrade(d) { d.createObjectStore('pending', { keyPath: 'id' }) },
})

async function enqueueUpload(blob: Blob, meta: object) {
  const id = crypto.randomUUID()
  await (await db).put('pending', { id, blob, meta, retries: 0 })
  // Chrome/Android：注册 background sync；iOS 会静默失败，走下面的兜底
  const reg = await navigator.serviceWorker?.ready
  await (reg as any)?.sync?.register('flush-uploads').catch(() => {})
  flushQueue() // 立即尝试
}

async function flushQueue() {
  if (!navigator.onLine) return
  const all = await (await db).getAll('pending')
  for (const item of all) {
    try {
      const fd = new FormData()
      fd.append('image', item.blob, `${item.id}.jpg`)
      fd.append('meta', JSON.stringify(item.meta))
      await uploadWithProgress('/api/upload', fd, () => {})
      await (await db).delete('pending', item.id)
    } catch { /* 留在队列，下次重试 */ }
  }
}
// iOS 兜底：网络恢复 / 回前台时刷队列
window.addEventListener('online', flushQueue)
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'visible') flushQueue()
})
```

真正的**断点续传**（大文件分片 + `Content-Range`）对你 100KB-1MB 的图片属于过度设计；上面的重试队列足够。若将来要传视频再上 **tus 协议**（`tus-js-client`，天然可续传）。

**中国浏览器差异**：微信里 Service Worker 不可靠，Background Sync 基本无效，务必以 IndexedDB + 前台重试为主路径。

## 5. PWA 体验：Serwist + iOS standalone 坑

**用 Serwist（`@serwist/next`），不要用已弃维护的 next-pwa。** Serwist 是 next-pwa 的现代替代品，专为干净配合 Next.js 16 设计[[1]](https://blog.logrocket.com/nextjs-16-pwa-offline-support/)。

```ts
// next.config.ts
import withSerwistInit from '@serwist/next'
const withSerwist = withSerwistInit({
  swSrc: 'app/sw.ts',
  swDest: 'public/sw.js',
  disable: process.env.NODE_ENV === 'development', // 开发禁用，避免缓存干扰
})
export default withSerwist({ /* 你的 next config */ })
```

```ts
// app/sw.ts —— 分层缓存策略：App Shell 预缓存 / API 不缓存 / 图片 CacheFirst
import { defaultCache } from '@serwist/next/worker'
import type { PrecacheEntry, SerwistGlobalConfig } from 'serwist'
import { Serwist, NetworkOnly, CacheFirst, ExpirationPlugin } from 'serwist'

declare global {
  interface WorkerGlobalScope extends SerwistGlobalConfig {
    __SW_MANIFEST: (PrecacheEntry | string)[] | undefined
  }
}
declare const self: ServiceWorkerGlobalScope

const serwist = new Serwist({
  precacheEntries: self.__SW_MANIFEST, // App Shell 自动预缓存
  skipWaiting: true,
  clientsClaim: true,
  navigationPreload: true,
  runtimeCaching: [
    {
      // 上传/登录/鉴权：绝不缓存
      matcher: ({ url }) => /\/api\/(upload|auth|login)/.test(url.pathname),
      handler: new NetworkOnly(),
    },
    {
      // 图片：缓存优先 + 过期清理
      matcher: ({ request }) => request.destination === 'image',
      handler: new CacheFirst({
        cacheName: 'images',
        plugins: [new ExpirationPlugin({ maxEntries: 200, maxAgeSeconds: 7 * 86400 })],
      }),
    },
    ...defaultCache,
  ],
  fallbacks: {
    entries: [{ url: '/~offline', matcher: ({ request }) => request.destination === 'document' }],
  },
})
serwist.addEventListeners()
```

`app/manifest.ts` 用 Next 内置：`display: 'standalone'`、`start_url`、192/512 图标（含一个 `purpose: 'maskable'`）。

**iOS Safari PWA 已知限制**：

* **getUserMedia**：老的"standalone 下完全不弹权限"bug 已修（iOS 13.4/14 起）。但**路由切换反复弹权限**仍在（见第 3 节），加上 standalone 下相机权限**不持久化**——对策同样是持有稳定的 MediaStream 组件。
* **存储被回收**：iOS PWA 的 IndexedDB 可能被清理（尤其未安装到主屏时有 7 天上限）。你的离线上传队列必须请求持久化：`await navigator.storage.persist()`。
* **外链、推送**：standalone 里外链跳出到 Safari；Web Push iOS 16.4+ 才支持且要求已安装到主屏。

**中国浏览器差异（关键）**：**微信内置浏览器基本不支持 Service Worker / PWA 安装**；UC/QQ 走 X5 内核，SW 支持时好时坏。你的高中生用户极可能通过微信分享点开链接——此时 PWA 安装提示、离线缓存全都不生效。必须做微信检测并显示"点右上角 ··· → 在浏览器打开"的引导蒙层。

## 6. 触感体验：点击延迟、:active、震动

**300ms 延迟**：现代浏览器只要有 `<meta name="viewport" content="width=device-width">` 就已消除，**不需要 FastClick**。对个别元素残留延迟，加 `touch-action: manipulation` 禁用双击缩放即可。

**`:active` 在 iOS Safari 不生效**：经典解法是给 `<body>` 加空的 `ontouchstart`，全页 `:active` 就会生效：

```html
<body ontouchstart=""> ... </body>
```

**`navigator.vibrate`**：Android Chrome 支持，**iOS Safari 从不支持**（iPhone 上 Web 无触觉反馈 API）。所以震动只能当渐进增强：

```ts
function haptic(ms = 10) { navigator.vibrate?.(ms) } // iOS 上静默 no-op
```

**推荐的移动端触感 CSS 组合**：

```css
html { -webkit-text-size-adjust: 100%; } /* 防 iOS 横竖屏字体缩放 */
* { -webkit-tap-highlight-color: transparent; } /* 去掉灰色点击闪烁 */

button, .tappable {
  touch-action: manipulation;      /* 消除双击缩放延迟 */
  user-select: none;
  -webkit-user-select: none;
}
/* 触屏设备用 :active 做自定义按压反馈 */
@media (hover: none) {
  .tappable:active { transform: scale(0.97); opacity: 0.85; }
}

.scroll-area {
  overflow-y: auto;
  overscroll-behavior-y: contain;      /* 防下拉刷新 / 滚动链穿透 */
  -webkit-overflow-scrolling: touch;   /* 老 iOS 惯性滚动，现默认，保留无害 */
}
```

`overscroll-behavior: contain`：Chrome 63+ / Safari 16+；老 Safari 降级为无（仅失去防穿透，不报错）。

## 7. viewport 适配：100dvh、safe-area、软键盘

**`100dvh`**：Safari 15.4+ / Chrome 108+ / Firefox 101+ 支持 `dvh/svh/lvh`，iOS 16.4 完全没问题。但 iOS 上 `dvh` 会随地址栏显隐**动态变化，滚动时可能抖**。**全屏固定布局建议用 `100svh`（最小视口，内容不会被地址栏遮）**，或 `100dvh` 实测取舍。老内核降级用 JS 自定义属性：

```ts
// 降级：给不支持 dvh 的老 UC/QQ 内核用 --vh
const setVh = () =>
  document.documentElement.style.setProperty('--vh', `${window.innerHeight * 0.01}px`)
setVh(); window.addEventListener('resize', setVh)
```

```css
.full-screen { height: 100vh; height: calc(var(--vh, 1vh) * 100); height: 100svh; }
/* 浏览器从上往下取最后一条能识别的 */
```

**`viewport-fit=cover` + `env(safe-area-inset-*)`**（iOS 刘海/底部横条适配，iOS 11.2+）：

```html
<meta name="viewport"
  content="width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content">
```

```css
.app { padding-top: env(safe-area-inset-top); padding-bottom: env(safe-area-inset-bottom); }
.bottom-bar { padding-bottom: calc(12px + env(safe-area-inset-bottom)); }
```

`interactive-widget=resizes-content`（Chrome 108+）让 Android 软键盘弹出时缩内容而非缩视口。

**软键盘弹出保持底部按钮可见（visualViewport API）**：iOS Safari 软键盘**不缩布局视口**，固定底栏会被键盘盖住。用 `visualViewport` 把底栏顶上去：

```ts
// visualViewport: iOS 13+ / Chrome 61+ 支持
const vv = window.visualViewport
const bar = document.querySelector<HTMLElement>('.bottom-bar')!
function onResize() {
  if (!vv) return
  // 键盘高度 = 布局视口 - 可视视口 - 顶部偏移
  const keyboard = window.innerHeight - vv.height - vv.offsetTop
  bar.style.transform = `translateY(${keyboard > 0 ? -keyboard : 0}px)`
}
vv?.addEventListener('resize', onResize)
vv?.addEventListener('scroll', onResize)
```

降级：无 `visualViewport`（极老内核）时监听 `window.resize` + input `focus/blur` 粗略处理，或干脆让键盘弹出时把底栏 `position` 从 `fixed` 临时改为随内容滚动。

**中国浏览器差异**：UC/QQ 老 X5 可能不支持 `dvh` 和 `visualViewport`，两个降级路径都要保留;微信内 `visualViewport` 一般可用（较新 X5），但键盘行为在 iOS 微信里偶尔不触发 resize 事件，需实测。
